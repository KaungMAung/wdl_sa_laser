# SA-008 — Verify Clear Lot lifecycle

Status: DONE
Type: DB

## Purpose

Verify that one lot can be finalized while other active lots continue.

## Current Evidence

`services/run_service.py::clear_lot` and `services/inspection_store.py` implement lot finalization; ADR-005 confirms the intended semantics.

## Scope

Test complete and incomplete lot clearing, End snapshot creation, lot-level events, Current deletion, and preservation of other lots.

## Out of Scope

No code fix, Clear All, or explicit End Run implementation.

## Acceptance Criteria

- [DB] A complete lot produces `LOT_CLEARED`; an incomplete lot produces `LOT_CLEARED_INCOMPLETE`.
- [DB] Affected Current rows are copied to End and then removed.
- [DB] Other lots remain active and no `RUN_ENDED` is emitted.

## Verification Required

Inspect SQLite transaction results for two active lots and verify event/row counts.

## Dependencies

SA-006, SA-007

## Notes / Constraints

Use confirmed Clear Lot semantics in ADR-005.

## Implementation Summary

Added isolated SQLite lifecycle tests for complete and incomplete Clear Lot
operations. Coverage verifies confirmation warnings, End snapshot creation,
lot-level clear events, deletion of only the affected lot's Current rows, and
continued presence of another active lot. No production clear logic changed.
