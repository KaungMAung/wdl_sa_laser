# SA-015 — Verify TRAYDATA write and read-back mapping

Status: ALIGNING
Type: PLC

## Purpose

Verify that loaded lots write the intended tray/part payload and read back through the existing PLC structure.

## Current Evidence

`services/plc_data_service.py::write_tray_data` and `services/run_service.py` construct payloads for eight trays with seven application parts per tray.

## Scope

Use a controlled run to verify RunNo/ProdNo/LotCode/MaterialNo/NewTray/Done/SerialNo mapping, tray assignment, part indexing, and read-back state.

## Out of Scope

Do not change seven-part application behavior or decide whether PLC exports support ten parts.

## Acceptance Criteria

- [PLC] Writes are observed at the expected TRAYDATA tags and values match the run/lot/tray mapping.
- [PLC] Serial numbers remain associated with the intended tray and part.
- [PLC] Read-back populates the existing backend state without GUI-owned PLC access.
- [HUMAN] Machine/PLC owner approves safe test conditions.

## Verification Required

Capture tag-level read/write evidence for at least two lots and both trays of one lot.

## Dependencies

SA-014, SA-019

## Notes / Constraints

Export metadata lists ten elements in places; this task verifies current application contract only.
