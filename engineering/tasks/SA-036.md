# SA-036 — Reset all Clear All working state

Status: READY
Type: BUG

## Purpose

Correct Clear All so it resets every lot and batch working-state field,
including inactive and partially entered lots.

## Current Evidence

SA-023 reproduced stale inactive-lot state after Clear All. The confirmed rule
requires a clean working state for all active and inactive lot slots.

## Scope

Reset all transient lot/batch state after successful atomic persistence,
including Run/PO, Inspection Lot, Inspection Point, scanned serials, counters,
statuses/displays, loaded/staged tray data, and other working fields owned by
the cleared batch. Add automated regression coverage.

## Out of Scope

Do not change Clear All persistence atomicity (SA-035), Clear Lot semantics,
End Run semantics, PLC protocol, or historical database rows.

## Acceptance Criteria

- [AUTO] Clear All leaves every lot slot in its initial clean state,
  including slots without active Current rows.
- [AUTO] Partially entered and staged/transient batch state is cleared.
- [AUTO] Other historical Start/End/Event data is not deleted.

## Verification Required

Extend the isolated Clear All tests with inactive, partially entered, scanned,
counter/status, and staged-tray state, then run the full unittest suite.

## Dependencies

SA-009, SA-023, SA-035

## Notes / Constraints

Confirmed Clear All semantics are documented in ADR-005/ADR-006. Complete
Clear All atomic persistence (SA-035) before final state-reset verification.
Do not repurpose SA-023; it remains the characterization record.
