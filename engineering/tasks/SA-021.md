# SA-021 — Characterize configured connection-check interval behavior

Status: DONE
Type: BUG

## Purpose

Verify whether BackendPoller honors the configured SQL/PLC connection-check interval.

## Current Evidence

`services/backend_poller.py::run` polls on its two-second loop; `engineering/CURRENT_STATE.md` records that the configured 60-second connection-check interval is not honored.

## Scope

Run a fake-clock/fake-service poller and compare connection-check timestamps with configured interval and data-poll interval.

## Out of Scope

Do not alter retry or polling behavior.

## Acceptance Criteria

- [AUTO] Test evidence shows the effective connection-check cadence for representative configuration values.
- [CODE] Any divergence from the configured contract is recorded as a separate fix requirement.

## Verification Required

Use deterministic time control and captured service-call timestamps.

## Dependencies

SA-001

## Notes / Constraints

Do not confuse PLC data polling cadence with connection health-check cadence.

## Implementation Summary

Added deterministic fake-service characterization tests. They show that an
unloaded poller calls `check_connection` on every poll interval and that a
loaded poller performs result/status polling without a separate connection
check. No timing sleeps or production poller changes were introduced.
