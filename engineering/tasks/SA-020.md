# SA-020 — Characterize recipe workbook upsert reporting defect

Status: DONE
Type: BUG

## Purpose

Confirm whether existing recipe rows are counted as updated without an actual database UPDATE.

## Current Evidence

`services/recipe_service.py::import_workbook` selects existing rows and increments update reporting; the audit found no observed UPDATE operation in that branch.

## Scope

Run an idempotent import with changed and unchanged workbook values while tracing SQLite writes and import counters.

## Out of Scope

Do not change importer behavior or workbook data.

## Acceptance Criteria

- [AUTO] A repeatable case demonstrates actual INSERT/UPDATE/no-op behavior and reported counts.
- [DB] Changed existing values are compared with stored values and the discrepancy is documented.
- [CODE] A separate correction requirement is produced if behavior is confirmed defective.

## Verification Required

Use isolated SQLite and a fixture workbook; inspect SQL trace or row values before/after.

## Dependencies

SA-001

## Notes / Constraints

Preserve leading-zero normalization while characterizing the issue.

## Implementation Summary

Added a temporary-workbook characterization test covering an initial insert and
a second import with changed existing values. No importer code or workbook data
was changed.
