# SA-019 — Align unresolved PLC contract questions

Status: ALIGNING
Type: PLC

## Purpose

Obtain human/PLC-owner decisions for contract discrepancies before changing or expanding implementation.

## Current Evidence

`engineering/PLC_CONTRACT.md` records unresolved differences: seven vs ten parts, recipes 1–16 vs 1–20, HMI_RECIPE_SELECT_BIT vs RECIPE_SELECTED_BIT, CURRENT_RECIPE usage, and Done/NewTray semantics.

## Scope

Review exported tags, current code, and a safe PLC sequence with the responsible engineer; record explicit decisions for each discrepancy.

## Out of Scope

No application code or PLC program changes.

## Acceptance Criteria

- [HUMAN] A named PLC/business owner signs a decision for every listed discrepancy.
- [CODE] Decisions identify which current behavior remains the contract and what evidence would permit change.
- [PLC] Decisions are supported by tag/sequence observations where hardware behavior is relevant.

## Verification Required

Update engineering decision/contract documentation after review; do not mark unresolved items by assumption.

## Dependencies

None.

## Notes / Constraints

This is an alignment task, not permission to expand recipe or part ranges.
