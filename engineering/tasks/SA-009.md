# SA-009 — Verify Clear All semantics

Status: IN_REVIEW
Type: DB

## Purpose

Verify that Clear All finalizes every active lot without explicitly ending the run.

## Current Evidence

ADR-005 confirms Clear All is equivalent to Clear Lot for every active lot and must not emit `RUN_ENDED`; current implementation has a known reset/transaction gap.

## Scope

Exercise Clear All with complete, incomplete, and inactive lots; verify lot-level End rows/events and reset of all working state.

## Out of Scope

No implementation fix and no End Run semantics.

## Acceptance Criteria

- [DB] Every active lot is finalized and its Current rows are deleted.
- [DB] Each affected lot receives the appropriate lot-level clear event.
- [DB] No `RUN_ENDED` event is emitted.
- [AUTO] Inactive lot state is cleared and no unrelated historical rows are deleted.

## Verification Required

Run isolated multi-lot scenarios and inspect SQLite plus returned RunService state.

## Dependencies

SA-008

## Notes / Constraints

Confirmed behavior is documented in ADR-005; failures should become separate implementation tasks.

## Implementation Summary

Added isolated Clear All characterization tests. They verify that active lots
are finalized to End, Current rows are removed, lot-level incomplete-clear
events are recorded, and no `RUN_ENDED` event is emitted. The test also records
the current implementation gap: an inactive lot's stale in-memory input is not
reset by `RunService.clear_all_lots`. No production code was changed.
