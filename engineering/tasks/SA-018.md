# SA-018 — Verify PLC communication-loss and reconnection behavior

Status: ALIGNING
Type: PLC

## Purpose

Verify that polling survives communication loss and automatically resumes without losing last-known state.

## Current Evidence

`services/backend_poller.py` catches polling errors and `services/plc_data_service.py` manages connection state; no complete hardware acceptance record exists.

## Scope

Disconnect/reconnect the PLC during an active run and observe status, retained data, retry behavior, and resumed updates.

## Out of Scope

No retry-policy redesign or GUI architecture changes.

## Acceptance Criteria

- [PLC] Backend reports disconnected without crashing and retains last-known tray/disc information.
- [PLC] Reconnection returns to connected and polling resumes automatically.
- [HUMAN] Engineer confirms no duplicate poller or duplicate event stream is created.

## Verification Required

Use controlled network/PLC interruption with timestamped backend logs and API/SQLite evidence.

## Dependencies

SA-013, SA-016

## Notes / Constraints

Do not treat a successful mock reconnect as real PLC verification.
