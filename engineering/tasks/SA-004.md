# SA-004 — Verify role authorization across API routes

Status: DONE
Type: API

## Purpose

Prove backend authorization, independent of frontend menu visibility.

## Current Evidence

Role guards are implemented in `api/recipe_api.py`; role definitions and user storage are in `services/auth_service.py`.

## Scope

Exercise production, recipe, settings, and user-management endpoints as each role and unauthenticated caller.

## Out of Scope

No changes to role policy or GUI routing.

## Acceptance Criteria

- [API] Operator can use production routes but receives authorization failure for Recipe, Settings, and Users routes.
- [API] Engineer can use Recipe and Settings routes but not Users routes.
- [API] Admin can use all permitted routes.
- [API] Unauthenticated requests are rejected where authentication is required.

## Verification Required

Run a matrix of authenticated HTTP requests and record status codes without relying on hidden UI controls.

## Dependencies

SA-003

## Notes / Constraints

The matrix must reflect `engineering/DECISIONS.md` and not infer additional permissions.

## Implementation Summary

Added HTTP-boundary role authorization tests using temporary SQLite user stores
and a minimal backend/recipe façade. The tests verify production access for all
roles, Recipe and Settings access for Admin/Engineer only, and Admin-only User
Management access. No authorization policy or production behavior was changed.
