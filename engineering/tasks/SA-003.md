# SA-003 — Verify authentication and session lifecycle

Status: DONE
Type: API

## Purpose

Establish repeatable evidence for login, current-user lookup, logout, expiry, and failure handling.

## Current Evidence

At task start, `services/auth_service.py::AuthService` used PBKDF2 and
in-memory sessions; routes are handled by `api/recipe_api.py`. No formal
authentication tests were recorded.

## Scope

Test `POST /api/auth/login`, `GET /api/auth/me`, logout, invalid credentials, inactive users, and session expiry using a controlled clock or short timeout.

## Out of Scope

No password policy redesign, persistent token redesign, or UI implementation.

## Acceptance Criteria

- [API] Valid credentials create a session accepted by `/api/auth/me`.
- [API] Invalid/inactive credentials are rejected without exposing password hashes.
- [API] Logout invalidates the session and expiry is enforced.
- [AUTO] Tests never log or assert plaintext passwords.

## Verification Required

Run authenticated requests against an isolated SQLite database and inspect responses/log capture.

## Dependencies

SA-001

## Notes / Constraints

Preserve Admin/Engineer/Operator roles and current in-memory session semantics unless a separate decision changes them.

## Implementation Summary

Added HTTP-boundary authentication tests using temporary SQLite user stores and
the existing stdlib `RecipeApiServer`. Coverage includes bearer tokens, HTTP
session cookies, invalid credentials, inactive users, logout invalidation,
secret-safe responses/logs, and deterministic session expiry using a test-only
clock patch. No production authentication policy or session architecture was
changed.

## Verification Evidence

- [API] `python -m unittest discover -s tests -v`
  - Result: 8 tests passed, 0 failures, 0 errors.
- [AUTO] `python -m compileall -q api api_main.py services tests`
  - Result: exit code 0.
- [API] Valid bearer and cookie sessions were accepted by `/api/auth/me`.
- [API] Logout caused both bearer and cookie sessions to be rejected afterward.
- [API] Invalid credentials and inactive users returned HTTP 401 without
  password hashes or plaintext secrets in responses/log capture.
- [API] A deterministic clock advanced beyond the default eight-hour lifetime;

- [CODE] Session state remains held in `AuthService.sessions`; no persistent
