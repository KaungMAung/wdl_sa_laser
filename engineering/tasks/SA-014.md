# SA-014 — Verify PLC recipe selection and LaserProgramNo contract

Status: ALIGNING
Type: PLC

## Purpose

Verify fail-fast recipe selection against the physical PLC.

## Current Evidence

`services/plc_data_service.py::prepare_recipe_selection` reads `RECIPE<n>.ID`, writes/read-backs `LaserProgramNo`, and writes/read-backs `HMI_RECIPE_SELECT_BIT` using signed 16-bit one-hot conversion.

## Scope

Test valid recipe IDs, ID mismatch, unavailable recipe tags, LaserProgramNo read-back failure, select-bit read-back failure, and no TRAYDATA load after failure.

## Out of Scope

Do not decide recipe range expansion or replace the selected bit tag.

## Acceptance Criteria

- [PLC] Valid selection writes the expected LaserProgramNo and signed one-hot select value, including Recipe 16 = -32768 if supported by the agreed contract.
- [PLC] Any verification failure blocks TRAYDATA loading and exposes/logs the exact failure.
- [HUMAN] PLC engineer confirms tag values and safe test procedure.

## Verification Required

Capture PLC reads/writes and backend logs for each fail-fast branch.

## Dependencies

SA-013, SA-019

## Notes / Constraints

Current code uses HMI_RECIPE_SELECT_BIT and limits polisher IDs to 1–16; both remain provisional.
