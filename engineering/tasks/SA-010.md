# SA-010 — Verify explicit End Run semantics

Status: DONE
Type: DB

## Purpose

Prove that End Run is the only explicit run-level termination action.

## Current Evidence

ADR-005 defines End Run as finalizing all remaining Current rows and emitting one `RUN_ENDED`; `services/run_service.py` and `services/inspection_store.py` contain the relevant paths.

## Scope

Test End Run with multiple active lots, including incomplete discs, and verify End snapshots, Current deletion, one run-level event, and cleared active state.

## Out of Scope

No Clear Lot/Clear All implementation changes.

## Acceptance Criteria

- [DB] All remaining Current rows are copied to End and removed.
- [DB] Exactly one `RUN_ENDED` event is recorded for the run.
- [DB] Active run/lot state is cleared after confirmation.
- [AUTO] Incomplete discs are reported but do not prevent the confirmed action.

## Verification Required

Inspect isolated SQLite lifecycle rows and returned service state before/after End Run.

## Dependencies

SA-006, SA-007

## Notes / Constraints

Do not count Clear All or Clear Lot events as `RUN_ENDED`.

Added isolated End Run lifecycle tests covering the incomplete-run
confirmation warning, finalization of all remaining Current rows, deletion of
active rows, immutable End snapshots, and exactly one run-level `RUN_ENDED`
event. No production end-run logic changed.
