# SA-013 — Verify PLC connection and single-poller ownership

Status: ALIGNING
Type: PLC

## Purpose

Verify connection behavior, backend ownership, reconnect handling, and absence of duplicate production pollers on real hardware.

## Current Evidence

`services/plc_data_service.py::PLCDataService` uses pycomm3; `services/backend_poller.py::BackendPoller` is started by `api_main.py`; historical logs show PLC communication but not acceptance testing.

## Scope

Start backend with the approved PLC, observe connect/disconnect/reconnect, verify one poller, and verify GUI closure does not stop polling.

## Out of Scope

No tag contract changes or recipe/tray write validation.

## Acceptance Criteria

- [PLC] Backend reports connected when hardware is reachable and disconnected without crashing when unavailable.
- [PLC] Reconnect restores polling after communication loss.
- [PLC] Process inspection confirms exactly one BackendPoller/PLC owner.
- [HUMAN] Engineer signs off on the observed behavior.

## Verification Required

Use process/log evidence and controlled PLC disconnect/reconnect; record timestamps and backend instance identity.

## Dependencies

SA-001

## Notes / Constraints

Requires access to PLC `192.168.1.10` or the configured target; do not infer success from mock mode.
