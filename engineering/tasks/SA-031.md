# SA-031 — Correct recipe importer existing-row upsert behavior

Status: READY
Type: BUG

## Purpose

Correct the confirmed mismatch between recipe importer update reporting and
stored existing-row values.

## Current Evidence

SA-020 reproduced `updated=1` while changed existing recipe values remained
unchanged in SQLite. Evidence is in `tests/test_recipe_import_characterization.py`.

## Scope

Define and implement safe update behavior for existing `material_no` rows while
preserving idempotence and text normalization.

## Out of Scope

No PLC recipe writes or LOAD DATA changes.

## Acceptance Criteria

- [AUTO] Changed workbook values update the matching SQLite row and persisted
  before/after values are asserted.
- [AUTO] Unchanged rows are idempotent and counters accurately distinguish
  inserts, updates, skips, and errors.
- [DB] No unrelated recipe rows are changed.

## Verification Required

Extend the SA-020 fixture with changed and unchanged rows after implementation.

## Dependencies

SA-020

## Notes / Constraints

The importer must preserve idempotence and uniqueness while making reported
updates real persisted updates.
