# SA-033 — Honor configured connection-check interval

Status: READY
Type: BUG

## Purpose

Align BackendPoller connection-health checks with the configured interval while
preserving the existing result/status polling cadence.

## Current Evidence

SA-021 showed that `BackendPoller` calls `check_connection` on every poll when
no tray data is loaded and has no separate connection-check interval field.

## Scope

Implement separate connection-check scheduling using the existing
configuration value, with deterministic tests for loaded and unloaded states.

## Out of Scope

No PLC protocol or status/result mapping changes.

## Acceptance Criteria

- [AUTO] Configured connection-check intervals produce the expected service-call
  cadence without sleeps or overlapping polls.
- [AUTO] Result/status polling remains at its configured data-poll interval.

## Verification Required

Extend SA-021 fake-clock coverage after implementation.

## Dependencies

SA-021

## Notes / Constraints

Idle connectivity checks and active Result/Status polling remain separate
cadences.
