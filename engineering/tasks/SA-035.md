# SA-035 — Implement Clear All transaction atomicity

Status: READY
Type: BUG

## Purpose

Implement atomic persistence semantics across all lots for Clear All.

## Current Evidence

SA-024 injected a second-lot failure and observed the first lot committed to End
while the second remained Current, proving separate transaction scope.

## Scope

Use one logical persistence transaction for all affected lots.

## Out of Scope

Do not reinterpret Clear All as End Run or change event names.

## Acceptance Criteria

- [AUTO] Failure-injection regression test proves a failed Clear All leaves all
  affected Current/End/Event rows unchanged.
- [DB] A successful Clear All archives/deletes all affected lots together.
- [AUTO] Clear All never emits RUN_ENDED.

## Verification Required

Run SA-024 failure-injection coverage after implementation.

## Dependencies

SA-024

## Notes / Constraints

Clear All must not reset in-memory state unless persistence succeeds.
