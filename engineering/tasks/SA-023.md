# SA-023 — Characterize Clear All in-memory reset gap

Status: DONE
Type: BUG

## Purpose

Determine whether Clear All resets every lot state, including lots without active Current rows.

## Current Evidence

`services/run_service.py::clear_all_lots` iterates lots with active Current rows before calling `finish_batch`; the audit identified a possible stale in-memory state gap.

## Scope

Exercise active, partially initialized, and inactive `LotState` instances and compare post-Clear-All memory/API state with ADR-005.

## Out of Scope

No implementation fix and no persistence semantics redesign.

## Acceptance Criteria

- [AUTO] A deterministic case proves whether every lot/input is reset.
- [CODE] Any mismatch is recorded as a focused correction task.

## Verification Required

Assert all four lot snapshots and batch fields after Clear All using fake services.

## Dependencies

SA-009

## Notes / Constraints

Confirmed intended behavior is in ADR-005 even if current code differs.

## Implementation Summary

Added a focused characterization test for inactive lot inputs during Clear All.
It confirms the current implementation leaves stale Run No., Inspection Lot,
and Inspection Point values on an inactive lot, matching the gap observed in
SA-009. No production reset behavior was changed.
