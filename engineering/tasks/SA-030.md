# SA-030 — Correct expected scan rejection logging severity

Status: READY
Type: BUG

## Purpose

Correct expected operator validation logging so normal input rejection is not
logged as an application error.

## Current Evidence

`api/recipe_api.py::_Handler.do_POST` catches all operation exceptions and calls
`LOGGER.exception("Backend API POST failed")`. SA-005 API tests observed stack
traces for expected duplicate and invalid serial responses while the API still
returned the correct HTTP 400 errors.

## Scope

Assess logging severity, operator-facing diagnostics, and production log volume
for expected `ValueError` validation failures.

## Out of Scope

Do not alter scan validation or API response semantics. Unexpected exceptions
and actual system failures must continue to log ERROR with traceback.

## Acceptance Criteria

- [CODE] Confirm the affected exception classes and current log output.
- [AUTO] Regression tests assert the chosen logging behavior.
- [AUTO] Expected duplicate, invalid-serial, and invalid-stage rejections are
  logged at an appropriate INFO/WARNING or structured validation level without
  stack traces.
- [AUTO] Unexpected exceptions still log ERROR with traceback.

## Verification Required

Update the API-boundary tests to capture expected and unexpected logging, then
run the full unittest suite.

## Dependencies

SA-005

## Notes / Constraints

The confirmed behavior is that expected business/input rejection is not a
system error.
