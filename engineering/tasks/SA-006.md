# SA-006 — Verify LOAD DATA Start and Current persistence

Status: DONE
Type: DB

## Purpose

Prove the transactional creation of immutable Start rows, active Current rows, and load events.

## Current Evidence

`services/inspection_store.py` implements `Inspection_Start`, `Inspection_Current`, and `Inspection_Event`; `services/run_service.py::load_data` coordinates loading.

## Scope

Load a controlled run with multiple lots/discs and verify UUID identities, snapshots, mapped PLC values, event rows, and transaction rollback on failure.

## Out of Scope

No PLC hardware, SQL Server, or implementation fixes.

## Acceptance Criteria

- [DB] One Start and one Current row exist per loaded disc.
- [DB] Each load creates the expected `LOAD_DATA` events with Run/Lot/Disc identifiers.
- [DB] Start rows are unchanged after later operations.
- [AUTO] A forced load failure leaves no partial Start/Current/Event set.

## Verification Required

Inspect isolated SQLite rows before and after load and assert UUID/Attempt_No relationships.
